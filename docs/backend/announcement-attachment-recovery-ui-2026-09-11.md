# 일반 첨부 작업 원복 UI 계약과 검증

## 목적·가정·범위

Design Read: 현재 공고의 일반 작업 이력을 찾아 원복 영향을 검토하고, 관리자가 이전 판정·검수 연결을 한 번만 복구한 뒤 불변 영수증과 현재 유효 상태를 구분한다.

- 사용자: ADMIN 승인, OPERATOR/APPROVER 조회. 기존 활성 계정·비밀번호 변경 완료·서버 역할 검증을 따른다.
- 과업: 일반 작업 탐색 → 현재 영향 확인 → 명시적 승인 → 영수증 확인 → 최신 기준 조회/후속 검수.
- 위험 R2: 잘못된 복구는 검수 의무와 초안 생성 가능 여부를 바꾼다. 현재 버전·원문1건·기본 경로 재개·이전 확인 복구 여부를 승인 전에 보인다. 강제 덮어쓰기·자동 승인·자동 공개는 없다.
- 기기 가정: 기존 관리자 데스크톱과 모바일360px, 키보드/터치. 기존 한국어·서울 시간대·Thymeleaf·Bootstrap 및 페이지 CSS를 유지한다. 새 라이브러리·모션은 없다.
- 이 회차는 일반 작업 UI다. 배치 수집/preview/적용/원복 화면·전체 분할 ledger·모든 Provider/profile·운영 E2E 범위를 대신하거나 완료로 축소하지 않는다.

## 화면과 API

기존 `/app/admin/collected-announcements/{sourceId}/attachments`의 근거 영역 아래 native details로 분리한다. 기존 수집/파일 재시도/역할 변경 폼과 별도이며 주 행동은 `확인한 공고 1건의 이전 연결 복구`다.

1. GET `attachment-recovery-jobs`로 모든 일반 작업을 페이지 조회한다. 실패·미적용·복구된 작업을 포함하고 batch 작업은 제외한다. 목록0건은 첨부0개나 전체 성공을 뜻하지 않는다.
2. 작업 버튼으로 GET `attachment-jobs/{jobId}/rollback/preview`를 조회한다. 원문/작업/버전/범위1·HTTP0·hash/모드/영향 형식을 검사한다. 별도 READY가 아닌 작업은 승인하지 않는다.
3. ADMIN이 사유와 비선택 기본값의 영향 확인 체크박스를 직접 입력한다. 입력 변경·작업 변경·최신 기준 조회 시 체크를 해제한다. 원문 내용을 폼이나 지문에 복사하지 않는다.
4. 동일 preview 기준 POST 원복을 승인한다. 기존 CSRF fetch wrapper와 UUID Idempotency-Key를 사용한다. 수집 예약202와 달리 이 API는 복구 transaction이 끝난200 영수증이다.
5. 응답의 원문/job/action/모드·복구 버전·영향·건수·HTTP0·기록 시각을 검사한 후 결과를 표시한다. 실패 예약의 원래 FAILED/PENDING은 유지되며 복구를 수집 성공으로 표현하지 않는다.
6. 목록의 actionId로 과거 원복 영수증을 재조회할 수 있다. 영수증은 현재 source 상태나 신규 검수 기록이 아니다. 복구 후 상단 최신 기준을 다시 조회하고 그 기준으로 검수/DRAFT를 판단한다.

page/size·원문 필터·응답 상세는 API 계약24.17을 따른다. 스키마 추가나 과거 migration 수정은 없으며 기존 V73의 job/action 연결을 읽는다. 불변 영수증이 없는 과거 이력에 새 영수증을 만들어 붙이지 않는다.

## 상태·복구·입력 보존

| 상태 | 화면·행동 |
|---|---|
| 조회 대기/실패 | 작업 조회 상태를 표시하고 재조회 버튼 제공. 실패를0건으로 표시하지 않음 |
| 조회 전용 | 영향·영수증 조회 허용, 승인 폼/버튼 잠금과 관리자 권한 설명 |
| READY | 영향을 읽고 사유·명시적 동의 후에만 승인. 자동 POST 없음 |
| 충돌/기존 근거 무효/작업 미종료 | 한국어 차단 사유, 강제 실행 없음. 최신 기준 조회 후 재검토 |
| 응답 유실/5xx/불일치 영수증 | 성공 미확정. 이 탭·최초 승인 계정·동일 키/본문 유지. 수집/검수/DRAFT/다른 원복 잠금 |
| 미확정 뒤401/403/409 | 최초 승인 결과를 추정하지 않음. 키를 새로 만들지 않고 계정 확인 뒤 동일 요청 재확인 |
| 확정409 | 사유 유지·동의 해제 필요·다른 변경 잠금. 최신 source/영향 재조회로 재시작 |
| 복구 완료 | 영수증 지속 표시, 새 source/검수 기준 조회. 자동 공고 활성화 없음 |

- 늦은 GET 응답은 세대가 바뀐 source/목록을 덮어쓰지 않는다. 원문 조회 실패 시 기존 승인 근거를 폐기하고 잠근다.
- 사유/멱등 키/요청 본문은 탭 메모리에만 보존한다. localStorage/sessionStorage·분석 로그·URL에 넣지 않는다. 이탈 시 미저장 입력/실행/미확정 경고를 사용한다. 브라우저 종료 뒤 사유를 복구하는 것은 개인정보 보존 정책상 제공하지 않는다.
- 비민감 `recoveryPage`/`recoveryJob`만 URL에 유지한다. 목록 조회는 GET이며 선택 상태 복원은 자동 승인이 아니다. 삭제 등으로 마지막 페이지가 비면 마지막 유효 페이지를 조회한다.
- HTML text node와 native button/select/textarea/checkbox/details를 유지한다. 오류는 alert와 폼 설명에 연결하며 성공·조회 상태는 live region으로 알린다. 영향 선택 후 제목에 포커스를 둔다. 기존 최소44px control·좁은 폭 세로 metadata·focus-visible CSS를 재사용한다.
