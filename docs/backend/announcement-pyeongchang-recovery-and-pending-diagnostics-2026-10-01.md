## 은평: 인코딩 차이는 404 해결 근거가 아님

공식 50607 상세의 `goDownLoad` 함수는 `encodeURI`를 적용하여 같은 호스트의 `/emwp/jsp/ofr/FileDown.jsp`를 요청한다. 현재 공통 처리기는 각 값을 query component로 인코딩하므로 파일 디렉터리의 `/`도 인코딩한다.

공식 상세 2회와 첫 파일 1회, 합계 3회만 조사했다. 실제 첨부 4개 중 첫 파일을 대상으로 공식 디렉터리의 `/`를 보존한 요청도 **HTTP404·HTML 1,040바이트**였다. 응답 SHA-256은 `94a8b78729d5cc1b896daa5b3598952f1ba7ab61ebda8ef5634737b020fee4d7`이며 첨부 파일 해시가 아닌 오류 응답 근거다.

따라서 인코딩 차이를 장애 원인으로 단정하거나, 효과가 입증되지 않은 공통 처리기 변경을 하지 않았다. 다른 내부 경로·미리보기·권한 우회도 하지 않았다. 나머지 파일을 같은 조건으로 반복 요청하지 않는다. 공식 서버 파일 제공 상태가 바뀌거나 새로운 공식 계약 근거가 확보되면 다시 검토한다.

## 송파: 공식 검색 문맥에서도 상세 제목 공백

공식 목록 `/www/selectGosiList.do?key=2776`의 검색 폼은 GET, 제목 검색은 `searchCnd=SJ`, 검색어는 `searchKrwd`다. ‘융자’ 검색 결과에서 기존 33174 제목과 상세 링크를 확인했다.

목록·검색·검색 결과의 정확한 상세 링크를 각 1회 조회했다. 검색 문맥을 보존한 URL도 HTTP200이나 `<th>제목</th>` 다음 `<td>`가 공백이었다. 이전 단순 URL만의 현상으로 볼 수 없다. 목록의 제목으로 상세의 빈 제목을 임의 덮어쓰거나 상세 식별 검증을 생략하지 않았다. 사이트의 데이터·템플릿·서버 원인 중 무엇인지는 미확정이다.
