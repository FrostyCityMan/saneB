이 문서는 Flyway `V65` seed와 관리자 초기 규칙 버전의 입력 명세다. `DRAFT_ENABLED`로 표시된 문구도 migration 적용만으로 운영 활성화하지 않는다. 초기 규칙 버전은 `DRAFT`로만 적재되며, 격리 QA와 관리자 활성화 이후 신규 수집부터 사용한다.

## 2. seed 상태

| 상태 | 의미 |
|---|---|
| `DRAFT_ENABLED` | 초기 DRAFT에 사용 상태로 적재할 후보 |
| `DRAFT_DISABLED` | 원문에는 있으나 오탐 위험 또는 해석 미확정으로 비활성 적재할 후보 |
| `METADATA_ONLY` | 발행기관 보호 구간 식별용이며 분류·제외 action은 없음 |
| `NOT_A_RULE` | 광범위하거나 역할이 잘못돼 초기 규칙으로 적재하지 않음 |

`DRAFT_DISABLED`와 `NOT_A_RULE`은 자동 제외나 자동 통과 근거가 될 수 없다.

## 3. 고정 판정 조건

1. 원격 검색이 가능한 제공자는 `지원대상 검색어 AND 지원유형 검색어` 조합으로 발견 범위를 만든다.
2. 원격 검색을 지원하지 않는 지자체 게시판은 행을 발견한 뒤 같은 공통 분류기로 판정한다.
3. provider 기관명과 기관 별칭의 전체 구간을 먼저 보호 metadata로 표시한다.
4. 보호 기관명 구간에 완전히 포함된 A·B·대상·지원유형 부분일치는 action을 적용하지 않는다.
5. 남은 제목에 그룹 B가 하나라도 있으면 그룹 A 포함 여부와 관계없이 `EXCLUDED`다.
6. 제목에 그룹 B가 없고 그룹 A가 있으면 `REVIEW_REQUIRED`다.
7. A·B가 없으면 제목의 지원대상과 지원유형 조합을 확인한다.
8. 제목 조합이 확인된 건만 본문 2차 판정으로 이동한다.
9. 그룹 B가 본문에서만 발견되면 자동 제외하지 않고 `REVIEW_REQUIRED`로 이동한다.
10. 첨부파일 이름, 확장자, 본문, OCR 결과는 어떤 판정에도 사용하지 않는다.
11. 기관명은 발행기관·주관기관 metadata로만 저장한다.
12. `EXCLUDED`도 원문과 판정 근거를 저장하며 물리 삭제하지 않는다.

## 4. 문자열 정규화와 일치 방식

### 4.1 정규화

판정기는 원문을 보존한 상태에서 별도 정규화 문자열을 만든다.

1. Unicode `NFKC` 정규화
2. 영문은 `Locale.ROOT` 기준 소문자 변환
3. HTML 본문은 script·style·숨김 요소를 제외한 보이는 텍스트만 사용
4. 줄바꿈·탭·연속 공백은 공백 하나로 축약
5. 일반 구분 기호는 단어 경계를 유지한 공백으로 정규화
6. 원문 위치 강조를 위해 정규화 문자와 원문 문자 위치의 대응표 유지

다음 동작은 하지 않는다.

- 한글 형태소 추정
- 오탈자 자동 보정
- 관리자 입력 정규식 실행
- 띄어쓰기 전체 제거
- 유사도·점수·확률 판정

### 4.2 일치 방식

| 코드 | 조건 | 예시 |
|---|---|---|
| `NORMALIZED_PHRASE` | 정규화된 연속 문구가 일치 | `정책자금`, `공무원 채용` |
| `TOKEN` | 영문·숫자 약어가 독립 경계에서 일치 | `R&D`, `IP`, `IR`, `PoC`, `TIPS` |
| `EXACT_TITLE` | 정규화된 제목 전체가 일치 | 매우 제한적인 행정 제목 |

띄어쓰기 변형은 암묵적으로 제거하지 않고 유의어로 적재한다. 예를 들어 `기간제근로자 채용`과 `기간제 근로자 채용`은 같은 규칙의 대표어·유의어다.

### 4.3 강한 키워드와 보조 키워드

| 강도 | 의미 |
|---|---|
| `STRONG` | 해당 지원대상 또는 지원유형을 직접 식별하는 문구 |
| `SUPPLEMENTARY` | 단독으로는 넓어 다른 강한 근거와 함께 사용해야 하는 문구 |

조합은 다음만 통과한다.

- `STRONG 대상 + STRONG 지원유형`
- `STRONG 대상 + SUPPLEMENTARY 지원유형`
- `SUPPLEMENTARY 대상 + STRONG 지원유형`

`SUPPLEMENTARY + SUPPLEMENTARY`는 제목 후보로 통과하지 않는다.

## 5. 발견 검색어와 분류 키워드 분리

모든 유의어의 곱집합을 외부 API 검색어로 만들면 호출 수가 폭증한다. 따라서 키워드 term에는 다음 속성을 둔다.

- `is_discovery_term`: 외부 검색식 구성에 사용할지 여부
- `discovery_order`: 제공자별 검색 순서
- `is_classification_term`: 수집 후 판정에 사용할지 여부

초기 원칙은 다음과 같다.

- 대표적인 강한 지원대상·지원유형만 `is_discovery_term=true`
- 장문 지역 표현과 유의어는 분류 전용
- 그룹 A·B와 공고 문맥어는 검색어가 아니라 후처리 분류 전용
- 동일 원문이 여러 검색 조합에서 발견되면 provider ID 또는 정규화 URL로 먼저 병합
- 실제 실행한 검색 조합과 규칙 버전을 수집 run에 보존

## 10. 의도된 충돌과 우선순위 예시

| 문구 | A 근거 | B 근거 | 결과 |
|---|---|---|---|
| 기술창업 지원사업 | A1 기술창업 | B2 기술창업 | 제목이면 `EXCLUDED` |
| 벤처기업 인증지원 | A3 벤처기업 인증·인증지원 | B2 벤처기업 | 제목이면 `EXCLUDED` |
| 수출인증 지원사업 | A3 수출인증 | B1 수출 | 제목이면 `EXCLUDED` |
| 친환경 인증 지원 | A3 인증 | B4 친환경 인증 | 제목이면 `EXCLUDED` |
| 해외인증 지원사업 | A3 해외인증 | B1의 `해외규격인증`과 불일치 | A 검수 |
| 중진공 소상공인 정책자금 | 없음 | 기관명은 B 아님 | 조합 판정 계속 |
| 소상공인 채용지원금 | 없음 | `채용공고`는 규칙 아님 | 조합 판정 계속 |
| 소상공인 대상 입찰 참여 지원 | 없음 | `입찰` 단독은 규칙 아님 | 조합 판정 계속 |
| 지원사업 고시 | 없음 | `고시`는 규칙 아님 | 대상 미충족 사유로 판정 |
| 소상공인 병의원 경영지원금 | 없음 | `의원`은 규칙 아님 | 조합 판정 계속 |

한 문구가 같은 그룹의 여러 규칙과 겹치면 모든 근거는 저장하되 최종 action은 한 번만 적용한다.

## 11. DRAFT 검증 조건

- 같은 그룹 안에서 정규화 term 중복 0건
- 대표어 없는 규칙 0건
- `TOKEN` 대상 영문 약어가 문장 내부 부분문자열로 일치하는 사례 0건
- B5 기관명이 `AUTO_EXCLUDE_B`에 포함된 사례 0건
- `NOT_A_RULE` 문구가 자동 제외 규칙에 포함된 사례 0건
- A/B 의도 충돌 목록이 모두 정답 세트에 존재
- 제목 B, 본문 B, 본문 없음, 첨부만 B인 사례가 각각 존재
- 모든 자동 제외 건에 source ID, 규칙 버전, 위치별 근거가 저장
- 세 제공자에 같은 제목·본문을 넣었을 때 같은 판정
- DRAFT 활성화 전 변경 건수와 사유별 분포를 관리자가 확인

## 12. 남은 정책 Gate

1. 첨부 원문의 장문 사업자·개인·가족 문구를 전부 활성화할지, 핵심어 중심으로 시작할지 최종 승인
2. B6 `DRAFT_DISABLED` 잔여 문구 중 활성화할 구체 문구 확정
3. `학생`, 학교명, `대표자`, `기업`, `주민` 등 넓은 대상어의 실제 표본 오탐 검수
4. 제공자별 외부 검색에 사용할 `is_discovery_term` 최소 집합 확정
5. 지자체 상세 본문 수집을 이번 구현 범위에 포함할지 결정

권장안은 핵심어 중심의 작은 DRAFT로 시작하고, 정답 세트와 실제 표본에서 확인된 문구만 다음 규칙 버전에 추가하는 것이다.
