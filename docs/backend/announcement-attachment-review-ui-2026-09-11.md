# 공고 첨부 검수 화면 계약

상태: 단건 근거 조회·검수 확인·DRAFT 화면 로컬 구현. 합성 API를 사용한 실제 브라우저 조작 표본 확인. 운영 E2E 검증 전이며 전체 Gate 4는 Not ready다.

## 목표와 설계 판단

- Design Read: 기존 Thymeleaf/Bootstrap 업무 화면의 위계를 유지하며 현재 적용 판정, 미리보기, 과거 근거, 관리자 확인과 비활성 초안 생성을 분리한다.
- 사용자: ADMIN/OPERATOR의 공고별 근거 확인·수동 다중 분류·DRAFT 생성. APPROVER는 조회만 한다. USER/PARTNER/REVIEWER는 서버에서 차단한다.
- 주요 여정: 수집 공고 검수 목록 → 공고별 첨부 화면 → 본문/집합/파일/추출 문단 및 분류 이력 확인 → 현재 기준으로 검수 확인 → 별도 영향 확인 후 DRAFT 생성 → 공고 관리.
- 위험: 조회 R0, 확인 및 초안 생성 R2. 외부 활성화는 없지만 분류/감사/초안 기록이 남으므로 명시적 확인과 중복 방지가 필요하다.
- 가정: 한국어 내부 운영자, 서울 시간, PC 키보드/마우스가 주 입력이며 360px 모바일·320px stress·확대를 지원한다. 외부 원문은 인증 정보 없는 http(s) 링크만 새 창으로 연다. 추출 원문은 메모리 DOM에만 표시하며 HTML 실행·브라우저 저장을 하지 않는다.

## 계약·상태

- `/app/admin/collected-announcements/{sourceId}/attachments`는 no-store 인증 화면이다. 데이터는 기존 V2 read API에서 읽으며 제목 제외/QA 대상은 404다.
- review-context에 `confirmedClassification`(현재 버전 확인+확정 대상/형태), `linkedAnnouncement`(연결 ID/코드)을 additive로 제공한다. 확인은 source/base/evaluation/set/version에 일치할 때만 반환하며 원문 메모·작성자·멱등키는 제공하지 않는다. 연결 존재는 현재 공고 활성 상태를 뜻하지 않는다.
- 현재 요약과 review-context의 모든 버전이 일치해야 쓰기 가능하다. 낡은 응답/409 뒤에는 쓰기를 잠그고 입력을 보존한다. 사용자가 최신 기준을 읽고 다시 확인해야 한다. 과거 집합/판정은 확인 기준을 바꾸지 않는다.
- 빈 집합, 첨부 없음, 발견 실패, 부분 실패, 처리 중, 품질 부족, 현재 판정 없음, 미리보기, 권한 없음은 별개로 표시한다. 오류를 0건/성공으로 대체하지 않는다.
- 확인은 지원대상/지원형태 각각 1개 이상, 검수 방법, 현재 모든 필수 사유의 개별 확인, 메모 및 영향 확인을 요구한다. 사유 변경 후에는 재확인한다. 미확인 값을 자동 체크하지 않는다.
- 확인 POST는 세션 내 동일 payload 재시도에 같은 UUID 키를 쓴다. 네트워크/5xx 결과 미확정 중에는 payload를 바꿔 재전송하지 않는다. 초안 생성 재시도도 동일 요청을 보존한다. 메모/원문은 localStorage/sessionStorage/로그/분석에 저장하지 않는다.
- DRAFT는 별도 폼이며 서버가 반환한 현재 확정 대상에서 대표값을 선택한다. 정책 게시·배치는 별도 필수 구현 Gate로 유지한다.

## 단건 수집 복구 UI 증분 계획

- Design Read: 주 과업인 근거 검수를 유지하고, 첨부 복구는 별도 접이식 영역에서 현재 공고 1건의 대상·요청량·버전 영향 확인 후 실행한다. ADMIN/OPERATOR 쓰기, APPROVER 조회를 유지한다. 외부 요청 및 검수 기준 변경 위험 R2, 한국어/서울 시간/PC 키보드와 320~1440px 기준을 적용한다.
- 전체 수집은 읽기 전용 collection-context의 버전·정책·실행 해시와 상한을 사용한다. 미적용 공고에 ENFORCE를 새로 연결하지 않는다. 실패 파일 재시도는 현재 집합 전체를 조회·대조한 후 허용된 실패 파일만 선택한다. 역할 변경은 전체 파일 역할을 제출하며 외부 요청 없이 새 근거와 재판정 작업을 만든다.
- 전체 수집 최대 HTTP 132회, 실패 파일 재시도 최대 `12 × (1 + 선택 파일 수)`회, 역할 변경 0회다. 다운로드는 입력한 바이트 상한 이내다. 수집/실패 파일 재시도는 합산 원문별 60초 간격·24시간 최대 3회이며 서버가 최종 검증한다.
- 예약 시 이전 확인은 STALE이며, 기존 근거/연결된 공고를 덮어쓰지 않는다. 복구는 새 결과 확인과 재검수이며 단순 취소/되돌리기 UI는 제공하지 않는다. 작업 예약 응답은 파일 처리 성공이 아니다. 작업 ID와 수동 상태 조회를 제공한다.
- 조회/저장 중 및 결과 미확정 중에는 검수/초안/다른 복구 작업을 함께 잠근다. 결과 유실은 동일 키·payload만 재시도한다. 409 후 사유 입력은 보존하고 최신 조건 재조회 후 파일/역할/영향을 다시 확인한다. 과거 집합 탐색은 복구 기준을 변경하지 않는다.
- 수용 기준: 순수 계약 Node 테스트, SSR·권한 MockMvc, 로컬 합성 API 브라우저의 예약/상태/409/결과 유실/조회 권한을 검증한다. 실제 worker·DB·운영 역할·공개 파일·격리 추출은 이 증분의 합성 증거로 대체하지 않는다.

## 접근성·검증

- 네이티브 제목/링크/버튼/fieldset/legend/details를 사용한다. 로딩·오류·성공은 지속 알림, 폼 오류는 요약/관련 영역 연결, disabled 사유를 텍스트로 제공한다. 페이지 전체 가로 스크롤을 피하고 근거는 줄바꿈한다.
- 자동 새로고침/자동 실행/낙관적 성공을 하지 않는다. 수동 재조회는 입력을 보존한다. 미저장 입력과 결과 미확정 중 페이지 이탈 경고를 제공한다. 보안상 새 브라우저 세션으로 메모 복원은 하지 않는다(SHOULD 예외: 개인정보 저장 방지, 원래 탭 보존 안내, 브라우저에서 세션 만료 검증 필요).
- 수용: 역할별 SSR/HTTP, XSS 문자열 textContent, 401/403/404/409/5xx/timeout, 멱등 재시도, 잘못된 근거 좌표, 부분 실패와 오래된 응답, 입력 보존을 테스트한다.
- 실제 운영 브라우저의 키보드·화면 폭·확대·focus-visible·스크린리더·대비·느린 요청·두 세션 충돌은 별도 필수 Gate다. 정적/Node/MockMvc 결과로 대체하지 않는다.
- 지표: 기존 감사의 확인/초안 성공 건수, 오류 코드별 실패, 재조회→성공 비율을 비식별로 검토한다. 새 외부 분석 SDK는 추가하지 않는다. 성능은 페이지 단위 목록/문단 길이 제한으로 관리하며 운영 CWV/실사용 성능은 아직 미측정이다.

## 2026-09-11 로컬 브라우저 증거

- 환경: MockMvc가 실제 Thymeleaf 레이아웃/새 화면을 렌더링하고 `build/attachment-ui-qa/index.html`을 생성했다. 세션 보안 값과 외부 CDN은 제거한다. `scripts/qa/attachment-review-fixture-server.mjs`가 loopback 임의 포트에서 합성 API만 제공한다. 화면에 합성 QA임을 명시한다. DB·인증 서버·Provider·운영 공고는 사용하지 않았다.
- 현재 API 응답과 파일/추출/판정 이력을 조회하고, HTML 문자열은 문자 그대로 표시됨을 확인했다. 본문 script/제목 img/파일명 b 태그가 DOM으로 삽입되지 않았다. 이모지 뒤 ‘지원금’ 코드포인트 1~4가 정확히 강조됐다.
- 본인(개인)을 추가한 다중 분류 저장 → 저장된 확정 대상에서 대표값 선택 → 소득 기준·영향 확인 → 초안 생성 응답/연결 표시를 확인했다. 새로고침 후에도 저장된 분류를 복원했다. **합성 성공 응답이며 실제 DB DRAFT 생성 증거가 아니다.**
- 409 뒤 메모 유지·쓰기 잠금 → 최신 기준 재조회 → 영향 확인 체크 해제·재확인 → 재저장 흐름을 확인했다.
- 합성 503 응답 유실 뒤 폼/재조회 잠금·동일 요청 재시도만 표시 → 기존 확인 ID 복구를 확인했다. 중복 생성 불변식은 Node/서버 단위 테스트에서도 검증하지만 최신 실제 PG 동시성 테스트는 미실행이다.
- OCR 필수 사유 누락 시 저장 차단, 사유 체크만으로 추출 텍스트 방법을 허용하지 않음, 원문 전체 직접 확인 방법 선택 후 허용을 확인했다.
- 미리보기는 확인 불가 사유를 표시하며 쓰기를 차단했다. 조회 전용 합성 화면은 `data-can-manage=false`에서 두 쓰기를 차단했다. 404는 원문/근거를 제거하고 쓰기를 잠갔다. 실제 역할별 인증은 MockMvc로 별도 확인했고 운영 세션 검증으로 간주하지 않는다.
- 320/360/375/768/1024/1440px에서 페이지 전체 가로 넘침이 없음을 확인했다. 360/320/1440px 스크린샷은 작업 대화에 기록했다. 320px에서 공통 html 최소 너비가 스크롤바 폭만큼 넘치던 문제를 화면 전용 CSS로 수정했다.
- 공통 버튼의 display 규칙이 hidden을 덮어 재시도 버튼이 노출되던 문제를 화면 전용 `[hidden]` 규칙으로 수정했다. 문서 내 H1은 공통 레이아웃 제목 하나로 유지했다. 입력 변경 시 영향 확인 체크를 해제한다.
- Enter로 ‘현재 판정으로 건너뛰기’를 실행한 뒤 focus ID=`attachment-current`, outline=solid를 확인했다. Enter로 본문 details를 열었다. 정상 시나리오의 브라우저 콘솔 오류는 0이었다. 전체 키보드 여정/스크린리더/대비 계측/200·400% 확대/느린 네트워크/실제 세션 만료/운영 두 세션 충돌은 아직 미검증이다.
- 전체 네트워크 HAR/Provider 요청량/운영 데이터 불변은 이 fixture로 증명하지 않는다. 실제 운영 URL·권한·최신 DB/코드 배포가 필요한 Gate는 유지한다.

재현: `SANEB_ATTACHMENT_UI_FIXTURE=true`를 명령 범위에만 지정해 `AnnouncementAttachmentViewControllerSmokeTest`를 실행한 다음 `node scripts/qa/attachment-review-fixture-server.mjs`를 실행한다. 출력된 loopback 주소로만 접속한다. QA 후 해당 Node PID·탭을 종료하고 viewport override를 해제한다. 합성 API 서버는 운영 배포 산출물에 포함되지 않는다.

## 2026-09-11 단건 복구 UI 구현·검증

- `saneb-attachment-operations.js`가 기존 GET collection-context/파일 목록/작업 상태와 POST 전체 수집·실패 파일 재시도, PUT 전체 역할 변경을 연결한다. 새 DB/API 계약이나 관리자 파서 선택은 추가하지 않았다. 최초 수집의 null 첨부 판정과 미리보기 판정도 구분한다.
- 파일 선택은 현재 판정의 setId/hash/원문·첨부 버전 및 전체 파일·처리 건수에 결합된다. `SEALED`와 고정 정책·연결 보호·작업 중복은 기존 서버가 최종 검증한다. 역할 변경은 수집 조건 API의 OFF 오류와 독립적이며 저장 근거만 재판정한다. 미리보기에서 역할을 바꿔도 새 검수 의무를 부과하지 않는다.
- 최신 기준 재조회 시 사유와 다운로드 입력은 유지하되 작업 종류·파일 선택·역할 변경값·영향 확인을 초기화한다. 상한보다 큰 기존 입력은 몰래 낮추지 않고 입력 검증을 요구한다. 이 증분은 단건이며 정책 활성화나 기존 데이터 일괄 적용 UI가 아니다.
- 표본 서버 테스트 8 suite/104건 통과. Node 29건(기존 20+새 복구 계약 9) 통과. 실제 PostgreSQL의 추가 실행은 없었다.
- 인앱 브라우저 합성 QA: 전체 수집 132회 상한/예약 대기/검수 잠금/작업 상태 조회, 성공 파일 선택 차단 및 실패 파일 1개 재시도 24회 상한, OFF에서 수집 차단·역할 변경 외부 요청 0회, Enter 키 역할 변경 예약을 확인했다.
- 409 최초 검증에서 복구 폼만 잠기고 검수 버튼이 남는 결함을 발견해 수정했다. 재검증에서 복구/검수 모두 잠김, 사유 유지, 최신 기준 조회 후 작업·영향 확인 초기화를 확인했다. 반대 방향인 검수 요청 충돌도 복구 예약을 잠그도록 공유 상태를 연결했다.
- 합성 응답 유실(503) 뒤 폼·검수·재조회 잠금과 동일 요청 재시도 버튼을 확인했다. 재시도 뒤 같은 작업 ID를 받았으며 합성 서버 집계는 jobs=1, version=8, confirms=0, drafts=0이었다. 이는 실제 DB 멱등성 실행 증거가 아니다.
- 합성 readonly에서 복구 fieldset/예약 버튼 비활성 및 권한 설명을 확인했다. 320/360/375/768/1024/1440px에서 문서 scrollWidth=clientWidth였다. 정상 시나리오 콘솔 오류 0. XSS용 파일명은 태그가 아닌 문자열로 표시됐다.
- 키보드 Tab으로 역할 선택에 진입했을 때 공통 `.saneb-main select:focus`가 전용 outline을 덮는 문제를 발견했다. 화면 범위의 우선순위를 보강한 뒤 focus-visible=true/파란 solid outline과 Enter 제출을 재확인했다. 최종 스크립트·CSS를 로드한 데스크톱/360px 스크린샷은 작업 대화에 기록했다.
