# 첨부 배치 관리자 작업 화면

## 설계와 검증 계약

Design Read: 운영 담당자가 전체 범위와 이번 배치를 구분하고, 수집·적용·원복의 영향을 읽은 뒤 관리자만 단계별로 승인한다.

- 대상: ADMIN(실행), OPERATOR/APPROVER(조회). 숙련된 내부 담당자, 한국어·서울 시각, 데스크톱 중심이나 작은 화면·키보드 사용을 지원한다는 가정이다.
- 주요 과업: 범위/배치 탐색, 수집 결과와 선택 검토, 적용/복구 진행 확인. 다수 원문의 판정/검수 유효성을 바꾸므로 R2로 취급한다. 운영 공고 자동 활성화·삭제·정책 게시를 이 화면에서 하지 않는다.
- 기존 Thymeleaf/Bootstrap/검수 CSS와 외부 JavaScript를 사용한다. 라이브러리·차트·모션 추가 없음.
- 경로: `/app/admin/announcement-attachment-batches`. 수집 공고 검수 메뉴에서 진입한다. 목록·배치 ID·페이지는 URL로 복원하며 사유/멱등 키/요청 본문은 탭 메모리에만 둔다.
- 순서: 범위 미리보기(외부 HTTP 0) → 고정 예약 → 수집 시작 → 봉인 결과 미리보기 → 적격 항목 직접 선택 → 적용 승인 → 결과 조회/중지/재개 → 원복 영향 조회/승인/결과 확인.
- 동의는 기본 해제이며 입력·대상·조회 기준 변경 시 해제한다. 접수 응답은 성공/원복 완료가 아니다. 전체/잔여/삭제/선택/실패/충돌 수를 구분한다. 단일 배치(최대 1000건)는 전체 기존 데이터 처리 완료가 아니다.
- 결과 유실 시 같은 키/본문 재확인만 허용한다. CAS 수집 제어는 별도 영수증이 없으므로 최신 상태를 읽고 사용자가 새 기준 사용에 동의해야 해제한다. 최초 요청 성공 여부를 추정하지 않는다.
- 선택 저장은 화면에 보이는 페이지만 덮어쓰지 않는다. 고정 미리보기의 전체 페이지를 검증하고 기존 선택을 보존한 뒤 새 전체 선택 목록을 보낸다. 지문/버전/개수 변경은 제출을 차단한다.
- 원문·근거 문자열은 textContent로만 표시하며 API가 반환하지 않은 원문/삭제 ID/URL은 복원하지 않는다. 본문·첨부 확인은 기존 단건 검수 경로로 이동한다.

성공 기준: API 계약대로 실제 요청·권한·버전·영향·선택 범위가 결합되고 오류 후 중복 실행 없이 회복하며 결과 집계를 잘못 표시하지 않는다. 실패 기준: 보이지 않는 선택 소실, 페이지 일부를 전체로 표시, 미확정 요청의 자동 재생성, 접수를 완료로 표시, 실패/삭제 분모 제거, 정책/운영 공고 자동 변경.

SHOULD 예외: 민감할 수 있는 사유의 자동 저장은 하지 않는다. 탭 종료 시 입력이 사라질 수 있으므로 이탈 경고와 비민감 배치 URL 복원을 제공한다. 서버의 승인 이력과 탭 입력을 구분한다. 검증은 Node 상태 테스트와 실제 브라우저 후속 검증으로 분리한다. 자동 테스트만으로 반응형·키보드·스크린리더·대비 통과를 주장하지 않는다.
