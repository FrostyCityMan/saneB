# 첨부 전체 목록·고정 분할 관리자 화면

## 목표·설계 판단

Design Read: 최초 전체 대상과 현재 잔여·삭제·미예약을 대조하고, 선택한 고정 분할의 배치로 이동해 수집·적용·원복을 별도 승인한다.

- 사용자: ADMIN 변경, OPERATOR/APPROVER 조회. 숙련된 내부 담당자·한국어·서울 시각·데스크톱 중심 및 작은 화면/키보드 이용을 가정한다.
- 주요 과업: 전체 범위 확인/목록 고정, 분할 준비·배치 탐색, 전체 단계별 결과 대조. 이후 외부 요청·다수 판정 변경으로 이어지므로 R2로 다룬다.
- 기존 Thymeleaf/Bootstrap 5·검수 CSS·네이티브 폼·외부 JavaScript를 재사용한다. 새로운 라이브러리·모션·차트는 없다. Controller는 화면 모델만 구성하며 DB/API의 의미를 바꾸지 않는다.
- 경로: `/app/admin/announcement-attachment-backfills`. 기존 배치 화면에 진입 링크를 추가하고, 분할에서 생성한 배치는 저장된 `backfillRunId/backfillSegmentNo`를 통해 원래 전체 목록으로 돌아간다. 일반 배치는 연결을 만들어내지 않는다.
- 계약: V74 전체 범위/목록/소속, V75 예약/전체 집계와 API24.19~24.20. 새 migration 또는 운영 데이터 변경은 없다.

## 사용자 흐름·안전 경계

1. 전체 목록을 페이지로 탐색한다. 상세·분할 번호·페이지를 URL로 복원한다.
2. 게시 정책·출처·수집 기간·선택 마감일·분할 크기를 입력하고 전체 범위를 조회한다. `segmentSize`는 분할당 상한이며 전체 후보 수 제한이 아니다. 전체 후보 지문과 배타 보호 제외를 표시한다.
3. 전체 후보 수·범위 지문·분할 수·HTTP0과 목록 고정만 수행됨을 확인하고 관리자 사유·동의 뒤 생성한다. 작업/다운로드/분류 적용을 자동 시작하지 않는다.
4. 고정 분할의 원래 대상·잔여·삭제·입력 변화·정책/profile 준비를 조회한다. READY일 때만 예약 영향·상한·사유·동의 후 정확한 분할을 예약한다. URL·파서·profile·대상 ID 입력은 없다.
5. 예약 영수증에서 기존 배치 작업 화면으로 이동한다. 수집 시작/중지/재개/예약 취소/결과 선택/적용/원복의 승인은 기존 화면에서 각각 수행한다. 처음 예약된 SCOPE_READY를 수집 완료로 표현하지 않는다.
6. ALREADY_RESERVED는 기존 연결로 이동한다. 취소·실패한 배치를 교체하거나 삭제분을 다른 공고로 채우지 않는다. 재처리는 잔여의 새 전체 범위와 별도 승인으로 검토하고 원래 실패·취소 이력을 보존한다.
7. 전체 집계는 최초=잔여+삭제, 잔여=예약+미예약과 세 단계 각각의 분모를 검증한다. 수집/적용/원복 건수를 서로 더하지 않는다. 각 API의 조회 시점 차이가 있으므로 최신 조회 안내와 서버 재검증을 유지한다.

## 상태·오류 복구

- 초기 disabled, 읽기 권한, loading/aria-busy, 빈 목록/정책 없음/전부 삭제, 오류 요약, 입력 변경, 부분 조회 실패, 예약 준비 미충족, 서버 영수증을 구분한다.
- 조회 오류는 성공한 다른 조회로 숨기지 않는다. 대상/버전/전체 합계가 불일치하면 예약을 막고 최신 조회를 안내한다. 확인한 상위 목록과 영수증은 유지한다.
- 동의는 기본 해제이며 범위·사유 변경과 재조회 시 해제한다. 현재 대상이 달라진 상태에서 이전 동의를 사용하지 않는다.
- 멱등 쓰기는 UUID 키/본문을 탭 메모리에 고정한다. 응답 유실·잘못된 영수증 이후 401/403/409도 원래 결과의 실패 증거로 취급하지 않는다. 같은 요청 재확인 전 다른 변경·화면 내 이동을 막는다.
- 성공한 예약 뒤 목록 갱신만 실패하면 영수증/배치 링크를 보존한다. 새 예약으로 재시도하지 않는다. 원복/수집 API 호출은 이 화면에서 하지 않는다.
- 원문·근거를 HTML로 해석하지 않는다. 식별자와 상태는 textContent, 링크는 검증한 UUID의 내부 경로만 사용한다.
- 외부 역할/익명 SSR 접근을 차단한다. JS의 disabled만으로 권한을 보장하지 않으며 기존 서버의 ADMIN/CSRF/버전/멱등 검증이 최종 기준이다.

수용 기준은 일부 표본 예약의 성공이 아니라 원래 전체 후보와 모든 분할의 실처리 결과 대조다. 과거 승인 전체 이력 탐색, 정책 전체 QA/게시 화면, 전체 Provider/profile, Linux/실파일·운영 E2E는 여전히 필수다.

SHOULD 예외: 범위 입력/사유·요청 키의 브라우저 영구 자동 저장을 하지 않는다. 탭 종료·페이지 이동 시 미저장 입력이 사라질 수 있다. 비민감 ID·페이지 URL, 이탈 경고, 확인된 서버 이력/영수증, 다른 탭 로그인으로 보완한다. 자동 포트 시험은 반응형·키보드·스크린리더 통과 근거가 아니며 수동 검증은 별도다. 과업 성공 지표는 전체 분모 일치와 중복/누락 없는 예약·영수증 복구이며 테스트만으로 실제 사용자 접근성을 완료 처리하지 않는다.
