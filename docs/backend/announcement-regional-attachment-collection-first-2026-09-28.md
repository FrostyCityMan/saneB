## 사용자 지시와 변경된 순서

2026-09-28 사용자가 HWP 보완을 현재 단계에서 멈추고 모든 지역의 첨부 수집부터 마무리하도록 지시했다. 장기 목표 ATT001~062+SEG와9Gate를 축소하는 것이 아니라 실행 순서를 바꾼다.

- HWP1.0.16 추가 개발·실파일 재검증 중지. 앞서 발송한 화천 추가5요청 QA 질문은 실행 대기열에서 제외한다. 기존 원장6/7·중구32/32는 그대로다.
- 이미 실행 중이던 로컬 검사만 종료 확인: 전체 추출기251·서버 연동200·패키징20 실패/생략0, bootJar 성공. 이 결과는 지역 수집 완료나1.0.16 실파일 성공이 아니다.
- 우선 범위: 제목1차 정책을 통과한 공고의 공식 상세 식별 → 첨부 영역 발견 → 전체 파일 목록 → PDF/HWP/HWPX 실제 다운로드·signature/크기/hash 확인 → 원본 정리·수집 결과 기록.
- 본문 상세 HTML은 첨부 발견에 사용한다. 본문/첨부 텍스트 추출과 분류·구간 QA·정상 기대값은 이 단계의 선행조건으로 요구하지 않는다. 기존 제품 파이프라인이나 정책 게시 Gate를 제거하지 않는다.
- 파일이 부분 추출되거나 OCR/미지원 control이 있더라도 다운로드가 성공했다면 수집 근거로 사용할 수 있다. 반대로 HTTP200·페이지 열림·링크 발견만으로 다운로드 성공이라고 하지 않는다.

## 수집 단계 완료 조건

지역당 공식 고정 표본3건을 기준으로 확인하고, 최소1건은 실제 지원 형식 첨부를 포함해야 한다. 나머지 표본은 전체 파일 성공 또는 공식 첨부 영역의 없음 확인이 가능하다. 실제 제공되지 않는 PDF/HWP/HWPX를 억지로 요구하지 않으며 관측 형식·미관측 형식을 분리한다.

1. [ ] 해당 기관·현재 목록 파서·공식 상세·다운로드 경로 결합이 확인된다.
2. [ ] 제목 제외 정책을 우회하지 않는다. 제외 표본은 요청 중단 근거로만 남기며 수집 성공 표본 수에 넣지 않는다.
3. [ ] 공식 첨부 목록이 완전하고 모든 파일의 결과가 기록된다. 일부 성공·잔여 실패·미지원 형식은 미완료다.
4. [ ] 실제 binary·signature·응답 형식·크기·hash를 확인한다. 파일명만 보고 형식을 확정하지 않는다.
5. [ ] 소스/프로필 해시가 현재 코드와 일치하고 임시 원본이 정리됐다. 같은 공고를 중복 계수하지 않는다.
6. [ ] 모든 활성 지역의 결과가 대장에 있다. 접근 차단을 성공으로 바꾸지 않고 해당 지역을 남긴다.

이 조건은 **수집 단계 전용**이다. 추출 완료·정책 QA·운영 상시 처리·관리자 검수/DRAFT·전체 장기 목표 완료를 의미하지 않는다.
