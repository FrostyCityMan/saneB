이 후보의 과거 저장 본문에는 메뉴·푸터가 포함된 흔적과 과다 태그가 보인다. 이를 정제된 본문 또는 정확한 최종 분류로 제시하지 않는다. 이번 단건 첨부 작업과 과거 본문 갱신은 서로 다르며, 첨부 추출 성공으로 기존 본문 품질 문제를 감추지 않는다.

- 성공: 실제 공식 파일 처리 작업과 DB 추출 텍스트·근거가 존재하고, 같은 공고의 관리자 화면에서 확인된다.
- 부분 성공: 일부 파일만 성공한 경우 성공 근거와 실패 상태가 모두 남고 전체 성공으로 표시되지 않는다.
- 실패: 첨부 영역 발견 실패를 `첨부 없음`으로 표시하거나, 실패 파일이 사라지거나, 원문이 아닌 메뉴/파일명만으로 최종 분류한다.
- 공고별 최대80MiB, 기존 파일별·동시성 한도와 재시도 한도를 유지한다. 운영자가 파서를 임의 선택하지 않는다.

## 공고 입력 연계의 정확한 의미

첨부 텍스트를 적재한다고 모든 입력 필드를 자동 완성하는 것은 아니다. 첨부 검수 정책이 적용된 근거를 관리자가 확인한 후 별도 초안 생성 요청을 실행하면 제목·기관·수집 본문·신청 기간·확정 다중 분류가 비활성 DRAFT로 복사된다. 이후 조건 입력과 후속 승인이 필요하다. COLLECT_ONLY만으로 이 최종 전환 Gate를 충족했다고 보고하지 않는다.

## 복구와 잔여 위험

- 첨부 worker 문제 시 운영 설정을 비활성화하고 서비스를 재시작한다. 이미 적재된 근거를 임의 삭제하지 않는다.
- 정책 변경은 새 개정·QA·게시 절차로 수행한다. 실패한 게시 요청은 성공으로 기록하지 않는다.
- 과거 일정 실행 슬롯과 수집 실행 이력은 삭제하지 않았다. 재시작 도중 실행 슬롯이 남는 근본 복구 정책은 별도 개선 항목이다.
- 기업마당·정부24 API 인증 설정이 없으므로 지자체 수집 결과와 분리한다.
- 현재 접속은 HTTP이며 실제 서비스 공개 전 HTTPS 전환과 테스트 계정 정비가 필요하다.
- 이 단건은 실패 파일이 없는 성공 표본이다. 실제 운영 부분 실패 표본, PDF/HWP 운영 단건, 전체 지역 운영 수집 및 다음 정기 실행 성공은 이번 결과만으로 검증되지 않는다. Linux 회귀에서의 부분 실패 보존 검증과 구분한다.
- UI 시각 변경은 없다. 실제 운영 단건 예약·조회·문단 이동·구간 근거 및 콘솔을 확인했으며 모바일/스크린리더/모든 역할의 전체 회귀를 새로 실행한 것은 아니다.
